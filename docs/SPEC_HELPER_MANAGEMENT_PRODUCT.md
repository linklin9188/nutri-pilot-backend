## 产品定位重申

**Aieats = AI 家庭菜单 + 食材直采**

**不是**: 菲佣 HR 系统 / 招聘平台 / 工时打卡 / 健康档案

**是**: 围绕"今天家里吃什么"延伸的所有菲佣相关**时间安排** —
那不是"管菲佣", 是"让菲佣的时间在做饭这件事上更高效".

## 5 个时间维度的 Phase 拆解

### Phase 1 P0 — 菲佣进度雇主可见 (维度 #3, 2-3 小时)

**用户故事**: "我上班路上想知道菲佣今天做没做"

**改动**:
- migration `102_helper_cook_logs.sql` — helper_id / dish_id / served_date / status (pending/cooking/done) / completed_at
- HelperHome toggleTaskDone 双写 LS + DB (现有 trackCookCompleted 已写 user_chat_preferences, 这里加专业表)
- Home.tsx 加 "👩‍🍳 菲佣今日进度" 卡 (3 状态 chip): 早餐✓ 14:30 / 午餐⏳ / 晚餐⏰
- 雇主 push: 菲佣 mark done 触发雇主 Web Notification "午餐做好了"

**ROI**: 解 #1 雇主反馈痛点 80%, 工程 2 小时

---

### Phase 2 P0 — 跨日预制时间 (维度 #2, 3-4 小时)

**老板 5/27 原话**: "早餐可以吃昨晚做好拿出来热一下的东西".

**改动**:
- lib/breakfastPrepPhase.ts 分类: overnight (粥/包子/卤味) vs morning_fresh (煎蛋/三明治)
- HelperHome 晚饭后显示"今晚预制任务: 明早粥需要 30 分钟, 21:00 开始"
- 雇主菜单卡早餐每道菜旁 chip: 🌙 昨晚备 / ☀️ 现做
- cookSchedule 加 overnightPrepTime 字段

**ROI**: 解菲佣"早上忙不过来"+ 雇主"早餐质量稳定"

---

### Phase 3 P1 — 学新菜时间引导 (维度 #4, 4-6 小时)

**用户故事**: "菲佣下午 14-16 点空, 应该学新菜而不是刷手机"

**改动**:
- HelperHome 加新 section "📚 今天可以学的菜" (空闲时段才显)
- 算法逻辑: 算下一周菜单 - 菲佣已 cook 过的 (helper_cook_logs) = 待学清单
- 按 execution_level 从易到难
- 每道菜带视频 + 备菜清单

**ROI**: 菲佣自我提升 + 雇主菜谱扩展, 间接提升留存

---

### Phase 4 P1 — 采购时间窗优化 (维度 #5, 2-3 小时)

**改动**:
- VerifyIngredients 已有"哪天买什么"逻辑 (line 405+ tripDays)
- 加显示: 时间段 "周一 09:00-11:00 街市买海鲜 + 蔬菜"
- 跟菲佣 schedule 联动 (HelperHome 时间表加采购槽位)

**ROI**: 减少采购重复跑 + 雇主清楚菲佣什么时候出门

---

### Phase 5 — 不会做就反馈 (跨维度, 1-2 小时)

**用户故事**: "菲佣不会做今天这道菜, 直接跟 AI 说不会, 雇主收到提示"

**改动**:
- HelperCook 加 1 个按钮 "🆘 这道我没做过"
- 写 user_chat_preferences (helper_cant_cook, dish_id, household_id)
- 雇主 Home 触发提示 "菲佣说今天午餐不会做, 要换吗?"
- 算法 v73 下次少推该菜 (-0.5 confidence)

**ROI**: 沟通障碍解 + 雇主不用主动追问
