# SPEC — 雇主"想吃什么"主动点单飞轮 (TICKET-112)

> 老板 5/30 思路: 雇主侧做一个 chat 主动入口, 从食材出发选菜 → 看图/营养/味道
> → 加菜单 → 发菲佣做 + 同步采购。这是 STRATEGY_moat_4layers.md 里「食材飞轮
> P1」的落地。本 SPEC 把思路定稿。

## 1. 用户故事
作为在港大陆雇主, 我有时**明确想吃某样东西**(今晚想吃牛肉 / 冰箱有条鱼),
希望主动告诉爱吃, 它给我**该食材最受欢迎的做法**让我挑, 挑完一键变成菲佣
能做的菜 + 该买的料 —— 而不是只能被动接受算法推的菜单。

## 2. 痛点对齐 (老板 4 件事)
- [x] #2 每天吃什么 — 主动点单是被动推荐的补充 (讲究的用户用)
- [x] #1 菲佣做美味中餐 — 选完一键发做菜端, 菲佣看步骤做
- [x] #3 物美价廉买肉 — 选完同步采购清单 (提前一天下单)
- [x] #4 用户舒服 — 低门槛(点食材, 不用打字), 想吃啥精准给啥

## 3. 两个入口 = 两种时序 (关键设计)

| 入口 | 驱动 | 时序 | 落点 |
|---|---|---|---|
| **A「想吃什么」** 牛肉/鱼/鸡/虾/菜… | 嘴馋 | 可能要买 → **默认明天** | 加菜单 + **采购清单** |
| **B「冰箱有什么」** 拍照 / 打字原料 | 有料 | **今天就做** | 加**今日菜单** → 直接发菲佣 |

→ 天然解决"采购提前一天"矛盾: 嘴馋的走采购(明天), 有料的走今天做。

## 4. Chat 第一问 (文案 3 版, 老板选/改)

**版 A (温暖)**:
> 今晚想吃点什么?🍽
> 告诉我一样主食材, 我找最受欢迎的做法给你挑 —— 🥩牛肉 / 🐟鱼 / 🍗鸡 / 🦐虾 / 🥬蔬菜
> 或者, 冰箱里有什么?📸 拍张照 / 打字, 我看看能做什么

**版 B (省心)**:
> 想吃啥, 跟我说一声 👇
> [🥩牛肉] [🐟鱼] [🍗鸡] [🦐虾] [🥬菜] [🍳冰箱有的]

**版 C (主厨口吻)**:
> 主厨在听 👨‍🍳 今天想用什么食材?
> 选一样, 我把最受好评的做法端上来。

(默认版 B — chip 点选门槛最低, 符合"不用打字"。)

## 5. 食材 → top 10 做法 (排序逻辑)

入口 A 选"牛肉" → 查 `dishes WHERE main_ingredient` 命中牛肉相关
(beef/牛) → 按**爱吃热门分**排序取 top 10:
```
popularity = times_cooked * 0.4
           + employer_crown_likes * 0.3
           + repeat_rate * 0.2
           + health_score * 0.1
```
- **诚实**: UI 写"爱吃热门做法", 不冒充"下厨房 top 10"(我们没那数据)
- 时间过滤: prep+cook ≤ 60 min 优先 (跟 TICKET-101 一致, 汤豁免)
- 多样性: top 10 里 cook_method 去重 (别 10 道都是红烧)

入口 B 拍冰箱 → 复用现有 `scanMatch.ts` / fridgeDishes (拍照识别原料 →
匹配菜); 打字原料 → 同 main_ingredient 反查。

## 6. 菜品详情卡 (全复用现有数据)
点一道菜展开:
- 图: `image_url`
- 介绍: `description_zh`
- 营养: `protein_g / carb_g / fat_g / nutrition_kcal_per_serving` + 微量 → **本地算+展示, 不调 LLM**
- 味道: `flavor_tags` (麻辣/清淡/酸甜…) 中文标签
- 难度/耗时: `helper_friendly_score` + `cook_time_min`
- 小美可做: `xiaomei_compatible` → 显"小美一键做"徽章

## 7. 两个动作 + 双边联动

**[加入今日菜单]** (入口 B / 有料):
1. 写入今日 household 菜单 (今日 override 机制, 见 §9 决策点)
2. → 菲佣 `loadEmployerTodayMenu` 自动看到 (已有链路)
3. → 菲佣做菜端 `cook_steps_json` 已有步骤 + Tagalog (今晚刚翻完) → 直接做
4. 沉淀: 写 `user_chat_preferences` 高 confidence (主动选 = 0.9)

**[加入采购清单]** (入口 A / 要买):
1. 写入采购清单 (VerifyIngredients 读), 默认**明天**配送窗
2. `prep_steps_json` 的食材 → 采购项 (已有 tray/ingredient 结构)
3. 买到后 → 进菜单 → 发菲佣
4. 沉淀: 同样写偏好

**[★ 收藏到爱吃菜单]**: 写 `user_favorite_dishes`, 不入今日/采购, 纯偏好沉淀。

## 8. 飞轮闭环 (护城河 — 每步沉淀)
```
选食材 → 选做法 → 加菜单/采购 → 菲佣做 → 雇主吃→打分
   ↓        ↓         ↓                        ↓
 都写 user_chat_preferences / favorites (越用越懂)
   ↓
AI 营养对比(本地)+ 跨口味推荐(recommendVector 余弦) → 推没试过的 → 再选
```
每个 household 转半年 = 厚偏好数据 = 迁移成本 = 护城河 (见 STRATEGY 文档)。

## 9. 复用 vs 新建
**复用 (已有)**: dishes 全字段 / scanMatch 拍冰箱 / user_chat_preferences /
user_favorite_dishes / loadEmployerTodayMenu(菲佣可见) / cook_steps_json /
VerifyIngredients 采购 / recommendVector 跨口味。
**新建**: (a) 食材 chip 入口 UI; (b) 食材→top10 排序查询; (c) 菜品详情卡组件;
(d) "今日菜单 override" 机制 (见决策点); (e) 营养本地对比组件。

## 10. ⚠️ 要老板拍的决策点
1. **"加入今日菜单"怎么和算法生成的菜单共存?**
   - 默认我的方案: **append 加菜** (今日多一道, 不挤掉算法的) + 标"你点的"
   - 备选: 替换某个 slot (像现有 swap)
2. **入口 B 拍冰箱要不要保留打字?** 默认两者都留 (拍照 + 打字原料)。
3. **采购"明天"配送窗精确到几点?** 默认次日, 具体时段等"物美价廉买肉"谈完供应商再定。
4. **第一问文案** 选版 A/B/C (默认 B)。

## 11. 不变量
- 菜名/步骤真实一致 (不捏造, 见 feedback_no_fabricated_data)
- 营养对比本地算, 不烧 Gemini (见 feedback_minimize_gemini)
- 菲佣端展示走 EN/Tagalog (步骤已翻)
- "下厨房 top10"诚实改"爱吃热门", 不冒充外部榜
- 主动入口是**可选**的偏好调教, 默认仍算法推 (不破坏"省心"核心)

## 12. 分期
