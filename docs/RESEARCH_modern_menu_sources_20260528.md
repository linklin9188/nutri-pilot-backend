## 2. 每个数据源详细分析

### 2.1 黑珍珠餐厅指南 ★★★
- **是什么**: 美团/大众点评 2018 起每年发布的中国版"米其林"，对标本土口味
- **数据规模**: 2025 榜单内地+港澳约 330 家，分一钻(150+)/二钻(100+)/三钻(30+) [待核]
- **菜单展示**: 餐厅详情页有"必吃推荐 3-5 道"+ 用户晒图菜名，**非完整菜单**
- **获取方式**: dianping.com 网页可读；APP 强加密；**无公开 API**
- **反爬强度**: 极高 (Akamai + 自研指纹 + 行为分析)
- **法律风险**: **最高**。大众点评历史多次胜诉爬虫案 (2016 vs 食派士, 2017 vs 百度地图)，且明确将"商家信息+用户点评"作为受保护数据。
- **建议**: 不要爬。可由产品同事手工抄"必吃菜"做种子集 (300 家 × 3-5 道 ≈ 1000 道高质量菜名)，~3 人日。

### 2.2 米其林指南 ★★★★
- **数据规模**: 全球 17k+ 餐厅，亚洲中餐重点城市: 香港~70, 上海~50, 广州~30, 北京~30, 台北~30, 澳门~15 [待核]
- **菜单展示**: 餐厅页 1-3 道 "Chef's Recommendation"，含菜名+1-2 句描述
- **获取方式**:
  - 官网 HTML 公开 (guide.michelin.com)
  - 内部 API: `/api/restaurant/{slug}` 返 JSON，**未官方文档化**但可调
  - 无官方开发者计划
- **法律风险**: 条款禁止 systematic scraping，但米其林历史上对小规模学术抓取容忍度较高，执法弱
- **数据质量**: ★★★★★ (全球公认权威, 描述精炼)
- **建议**: 高优先级。香港 70 家 × 平均 2-3 道 = ~150 道, 上海+广州+北京 ~150 家 × 2-3 = ~400 道, 合计 ~550 道精品菜可建立"高端中餐种子库"。手工抄录 2-3 人日。

### 2.3 一饭封神 ★★
- **是什么**: 微信生态美食榜单, 由餐饮 KOL 团队运营，对标黑珍珠但更"民间口碑"
- **数据规模**: 推测覆盖 1k-2k 餐厅, 主打"封神菜"单品维度 (不是餐厅维度) [待核]
- **获取方式**: 微信公众号历史文章 + 小程序; 微信生态封闭, 无 API
- **法律风险**: 中-高。公众号文章版权归运营方; 小程序数据有腾讯 TOS 约束
- **建议**: 不直采。可做行业研究参考, 或商务联系合作 (用户量级匹配的话有谈判空间)

### 2.4 米其林指南 港澳版 (与 2.2 合并)
见 2.2.

### 2.5 下厨房 (xiachufang.com) ★★★
- **数据规模**: 200 万+ UGC 菜谱, 含家常中餐 ~70%
- **获取方式**: 网页公开, robots.txt 部分允许但 ToS 禁商用; GitHub 上多个 scraper repo (huangjianke/xiachufang 等), 多数 2-3 年未更新
- **数据质量**: 良莠不齐, "妈妈牌红烧肉"和"米其林同款"并存; 需筛选
- **法律风险**: 高。UGC 版权属用户, 平台 ToS 禁商用爬取
- **建议**: 不直采。作为"菜名 + 做法多样性"的灵感库 (公开搜热度榜手工抄 top 500 菜名), 不抄具体菜谱内容

### 2.6 小红书 ★
- **数据规模**: "中餐"/"网红菜"笔记数十万级
- **获取方式**: App 主导, 强反爬 (设备指纹 + 行为模型 + 频率限制), 网页版功能阉割
- **法律风险**: 极高。2024 年多起爬虫诉讼, 平台积极维权
- **建议**: 不爬。仅用作"哪些菜在年轻人中火"的人工调研入口 (产品同事浏览即可)

### 2.7 连锁品牌菜单 (太二/西贝/绿茶/海底捞/喜茶/奈雪/老乡鸡) ★★★★
- **数据规模**: TOP30 连锁品牌平均每家 50 SKU, 合计 ~1500 道
- **获取方式**:
  - 美团/饿了么外卖页 (有 SKU + 价格 + 销量)
  - 品牌官方小程序
  - 财报/招股书附录 (西贝/海底捞上市材料含菜单结构)
- **法律风险**: 中。菜名+描述属事实数据 (中国 2018 北京高院"大众点评 vs 百度"判决确立"事实数据非版权"原则), 图片有版权风险
- **数据质量**: 高 (品牌方专业)
- **建议**: **优先落地**。选 10 个香港 + 内地连锁 (海底捞/太二/西贝/绿茶/呷哺/喜茶/奈雪/老乡鸡/和府捞面/巴奴), 手工 + 半自动抄录, ~500 道现代化连锁菜, 3-5 人日

### 2.8 港式茶餐厅 (翠华/太兴/敏华/池记/星巴克 HK 限定) ★★★★★
- **数据规模**: 单家 80-150 SKU, TOP10 茶餐厅合计 ~1000 道
- **获取方式**:
  - 官网 PDF 菜单 (翠华/太兴有完整 PDF)
  - Foodpanda HK / Deliveroo HK / KeeTa 香港 (完整结构化, 含价格)
  - OpenRice 餐厅页 (用户上传)
- **法律风险**: 低-中。香港版权法对"菜单作为事实清单"保护弱; Deliveroo/Foodpanda 条款禁系统采集但执法稀
- **建议**: **香港市场必做**。半自动 + 人工, 2-3 人日可覆盖 TOP10 茶餐厅 ~800 道

### 2.9 OpenRice / Foodpanda / Deliveroo / KeeTa 香港 ★★★★★
- **数据规模**: Foodpanda HK ~8k 餐厅, Deliveroo HK ~5k, KeeTa ~6k, OpenRice ~25k
- **结构化程度**: ★★★★★ (外卖平台菜单天然结构化: 分类/SKU/价格/描述/图)
- **法律风险**: 中。SKU + 价格 = 事实数据, 版权风险低; 但平台 ToS 禁系统抓取
- **建议**: **最优结构化来源**。建议选 1 个平台 (Foodpanda 最完整) 抓 TOP500 香港中餐厅菜单 ≈ 1-2 万 SKU, 然后去重 + 聚合到"通用菜品"层 (e.g. "干炒牛河" 出现 200 次 → 1 道菜 + 200 个餐厅引用), 得到 ~2000-3000 道高质量香港现代中餐

### 2.10 海外华人中餐 (Panda Express / P.F. Chang's) ★
- 不推荐。美式中餐口味与香港/内地差异大, 跟产品定位不符

## 3. 老板可考虑的 3 个落地方案

### 方案 A: 完全人工 (从黑珍珠 + 米其林 + 连锁招牌菜手工抄录)
- **菜品规模**: 800-1200 道 (黑珍珠必吃 300 + 米其林招牌 400 + TOP10 连锁招牌 300)
- **人力**: 3 人日 × 1 名产品同事
- **成本**: 0 (内部人力)
- **法律风险**: 零 (人工抄菜名不构成爬取)
- **质量**: 极高 (全是榜单认证的"代表菜")
- **缺点**: 一次性, 不能持续更新; 数据维度浅 (只有名字, 缺价格/营养/做法)

### 方案 B: 半自动 (Foodpanda 香港 + 米其林 官网 爬虫 + 人工审核)
- **菜品规模**: 2000-3000 道香港现代菜 + 500 道米其林高端菜 = ~3000 道
- **人力**: 1 工程师 × 5 天 (写爬虫) + 1 产品 × 3 天 (审核去重)
- **成本**: 代理 IP ~$200/月 (单次抓取一次性 $200)
- **法律风险**: 中。Foodpanda 历史无中国/香港爬虫诉讼记录, 但条款禁; 控制频率 + 不存原图 + 不商用平台 logo 可降到可接受
- **质量**: 高 (含价格/分类/真实餐厅引用)
- **优点**: 可重复执行 (每季度刷新), 数据维度全
- **缺点**: 法律有 5-10% 风险被 cease-and-desist; 工程持续维护成本

### 方案 C: 合作 (跟某平台官方拿数据授权)
- **候选**: 米其林指南授权 / OpenRice API 商务合作 / 一饭封神品牌联名
- **菜品规模**: 取决于谈判 (米其林:数百道; OpenRice:数千餐厅)
- **人力**: BD/CEO 谈判 5-10 人日; 合同 + 法务 5 人日
- **成本**: 米其林预估 $50k+/年 (奢侈品授权); OpenRice 中等; 一饭封神 $10-30k 联名
- **法律风险**: 零 (有合同)
- **质量**: 顶级
- **缺点**: 周期长 (3-6 个月), 现金消耗大; 当前融资阶段不现实

## 4. 推荐组合 + 为什么

**短期 (本月落地)**: 方案 A + 方案 B Lite
1. **第一周**: 产品同事人工抄黑珍珠香港 + 米其林香港 + TOP5 港式茶餐厅菜单 ≈ 500 道**香港现代中餐种子集**, 替换/补强当前老化的内地家常菜库
2. **第二周**: 工程花 2 天写 Foodpanda 香港 TOP100 餐厅 单次爬虫 (不持续运行, 一次性补 1000-1500 道, 控频率 1 req / 5s, 不存图片), 法务风险可控
3. **审核**: 产品同事 3 天去重 + 标注 (打 ABCD 托盘 + 营养字段)

**中期 (Q3)**: 等用户量到 1 万再谈方案 C (米其林 / OpenRice 商务合作)

**为什么不直接做 C (合作)**:
- 当前 DAU 量级 (~百级) 谈不下来; 米其林这种品牌看重曝光量
- 现金应该花在用户增长不是数据授权
- A + B 已经能解决"菜单老化"这个老板的核心痛点

**为什么不只做 A (纯人工)**:
- 800 道菜对于一个生活方式 app 不够 (用户 1-2 个月就刷完了)
- 缺价格 / 分类 / 餐厅引用维度 → 不能做"附近哪家有这道菜"这种关键体验

**核心结论**: 现在做 **A (500 道精品种子) + B Lite (1500 道香港外卖菜 单次)**, 总投入 ~2 人周, 可让菜单库从"老化的家常菜 2k 道"升级为"4k 道现代化菜单含香港本地化", 这是最高 ROI 路径。

## 5. 待老板决策的关键点

1. **法务红线**: B 方案 Foodpanda 爬虫即使一次性, 老板是否接受 5-10% 的 cease-and-desist 风险? (实际不致命, 最多收信删数据)
2. **现代化定义**: "现代化"是指"网红菜/年轻人吃的菜"(小红书路线) 还是"高端餐厅菜"(米其林/黑珍珠路线)? 这两条路径不一样
3. **香港 vs 内地权重**: 产品当前国际化策略下 (TELEPOT-052), 应该 70% 香港 + 30% 内地, 还是 50/50?

研究员推荐答案:
- (1) 接受
- (2) **网红 + 高端混搭** (30% 米其林精品打高端心智 + 70% 茶餐厅/连锁打日常)
- (3) **70% 香港优先** (用户基本盘在港)
