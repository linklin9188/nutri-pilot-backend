# UI-030 首页路由跳转修 (P0 hot)

日期: 2026-05-24
ticket: TELEPOT-20260524-030
commit: ef3d1f2

## 解决了什么问题

老板真测打开 `https://nothinkeats.com/` (根路径)，应该看到 **login 页**让
用户先登录，但实际每次都被直接送到 **setup / onboarding 页**——跳过 login
关口。

根因: `src/App.tsx` `RootRedirect` 第 137-140 行采用 anonymous-first 模型
(注释明写 "visitors don't need to log in to use the app")，无 `quickPrefs`
直接 Navigate `/setup`，由 QuickSetup 内部 `crypto.randomUUID()` 写匿名
userId——首次访客根本看不到 `/login`。

老板新拍板: login 必须是第一关，未登录用户必须先过。

## 用了什么关键方法

router guard 三态逻辑 (CLAUDE.md custom-auth invariant):

1. **未登录** (`getUserId() === null`) → `<Navigate to="/login" replace />`
2. **登录但 onboarding 未完成** (有 userId, 无 quickPrefs) → `/setup`
3. **登录且 onboarding 完成** (有 userId + quickPrefs) → `<Home />`

实施细节:

- `getUserId()` 是 custom-auth 登录态唯一判定 (CLAUDE.md hard rule: userId
  在 localStorage, 不用 `auth.users`)，已在 `App.tsx` 顶部 import
- 新 guard 插在**微信 silent re-auth 分支之后** (`maybeAttemptSilent()`)，
  确保微信用户被静默登录回来再判定，不会被错误踢回 login
- 新 guard 插在 **role/quickPrefs 判定之前**，覆盖所有 anonymous 路径
- v3 升级路径 (line 124, `hasOldPrefs && !hasV3`) 留在 guard 之前——历史
  老用户有 quickPrefs 通常已登录，路径不动避免越界 refactor
- `?fresh=1` / `?ref=xxx` 分支不变 (本来就跳 `/login`)
- surgical edit: 只动 `RootRedirect`，不动 `Login.tsx` / `QuickSetup.tsx` /
  `userId.ts`
