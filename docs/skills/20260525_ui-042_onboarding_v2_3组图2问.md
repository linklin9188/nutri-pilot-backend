# UI-042 Settings 大重构第 4 棒 OnboardingV2 (3 组图 + 2 问)

日期: 2026-05-25
ticket: TELEPOT-20260525-042
spec: `docs/SPEC_settings大重构_老板拍板.md` §0.2 + §0.3
前置: Database 第 1 棒 commit `3d0b460`/`9da93d4` + Algorithm 第 2 棒 commit `5fa1740`

## 解决了什么问题

老板拍板 (SPEC §0.2): 老 11 题 QuickSetup 太长 (~3 分钟), 替代为 ~20 秒新流程
"3 组图 + 2 问"——用户选 12 张代表菜照片表达口味, 算法用 dish.feature_vector
加权平均推回 user.preference_vector (Spotify / Netflix 嵌入向量范式), 再问 2
个硬约束 (忌口 + 近期目标) 做硬过滤和营养重排。

设计目的: 让 onboarding 从"自我描述"(用户脑补"我口味偏什么")改成"看图选爱
吃的"(数据无歧义直接进算法), 配合 Algorithm 2 棒 ship 的 manual 20 维 embedding
+ cosine similarity 推荐路径走通。

### B. 2 问页 (Step 4)

**忌口** (多选 chip, 含"无"互斥):
- `seafood/nuts/gluten/milk/eggs` → `user_profiles.avoid_tags` text[] (allergen 硬过滤)
- `pork/beef/lamb` → `user_profiles.excluded_meats` text[] (肉类忌口)
- `none` → 选中清空所有, 互斥语义防"既选无又选别的"歧义

⚠️ **schema 偏离**: spec §0.2 写 "写入 user_profiles.allergens", 实查 user_profiles
**没有 allergens 列** (Database 部门 schema 落地用了已有 `avoid_tags`)。allergens 是
个人层级 (household_members), 不是全家层级 (user_profiles)。我用 `avoid_tags`
(已有字段, 已有 'gluten' 等真值) 等价覆盖, 算法侧硬过滤 reader 复用即可。

**近期目标** (5 选 1, 写 `user_profiles.dietary_goal`):
- `fat_loss` 减脂 / `muscle_gain` 增肌 / `general` 家庭 / `child_growth` 学龄 / `elder_wellness` 老人

dietary_goal 值跟 Algorithm 2 棒 `recommendVector.nutritionRerankScore()` switch case
完全一致, 不要乱起名 (algo 那边 hard-coded 这 5 个 case)。

### C. 提交流程 (finish())

1. ensure userId (没有则 crypto.randomUUID() + setUserId() 双写 'userId'/'nutri_user_id')
2. fetch 选中菜的 feature_vector (in 查询 uniqueIds)
3. `userVectorFromSelectedDishes(vectors)` 取平均得 20 维 user_vec
4. 拆 avoidSet → avoid_tags + excluded_meats
5. `UPSERT user_profiles` (id 是 text 主键, **不是** auth.users FK; CLAUDE.md
   hard rule: 主键 `id text`)
6. 写 `onboarding_v3_done='true'` + `onboarding_v2_done='true'` (RootRedirect guard 用)
7. 写 legacy compat: `userDiet` + `userAvoid` (下游 reader 复用)
8. 跳 `navigate('/')` — **不是** `/home`, 项目无 `/home` 路由, RootRedirect
   检测 onboarding_v3_done 后 render `<Home />`

### D. App.tsx 路由 + RootRedirect 调整

加 `/onboarding-v2` route (RequireAuth wrap, 防匿名直进)。

RootRedirect 末段三态:
- 有 `quickPrefs` (旧用户) → `<Home />` (保兼容, **不**强制旧用户重做)
- 有 `onboarding_v3_done` / `onboarding_v2_done` (新流程已完工) → `<Home />`
- 都没有 (纯新用户) → `<Navigate to="/onboarding-v2" />`

⚠️ **去掉了 TICKET-005 §E "v3 强制重做"分支**: 原 logic 把 quickPrefs 旧用户
拽到 /setup 重做 v3, 跟 spec §C 第 3 条 "保兼容, 不强制走新 onboarding" 冲突。
按 §C 优先 (更晚拍板) 删掉强制分支, /setup 路由保留可访问 (老用户主动重做 /
测试入口)。
