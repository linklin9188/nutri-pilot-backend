# TICKET-062 拍冰箱算法对齐主菜单 + 一键加今日菜单

## 1. 问题

老板真测发现两个硬伤:

1. **算法降级**: 拍冰箱推荐 (`src/lib/scanMatch.ts`) 只跑了简化版 5 轴 (ingredient match + dietaryGoal + tastePref + spice + xiaomei + fridge-mode), 完全没接主菜单 `scoreForWeek` 的核心三轴:
   - 家乡 (hometown) — 广东人扫到三文鱼推不出广式做法
   - prefScores 学习数据 — 用户用了一个月app, 拍冰箱时算法表现得像第一次见用户
   - family per-member — 备孕老婆 + 增肌老公的家庭, 拍冰箱给推减脂菜
   - 还有 v67 的 20-dim feature_vector 也没接

2. **没落地路径**: 拍完出来一堆菜, 点 card 只能跳 `/prep` 看做法, 用户关掉 Home 后这些菜全丢, 不会自动写回今日菜单. 用户必须自己手动去 WeeklyMenu 页找一遍重选, 体验断裂.

老板拍板 A + 1: 全对齐主菜单 5 轴 + 加 "+加今日菜单" pill.

## 2. 方法

### A. 算法对齐 (`src/lib/scanMatch.ts`)

加 4 个新轴 (保留原 ingredient match / dietaryGoal / tastePref / spice / xiaomei / fridge-mode 不动):

- **A1 hometown**: `hometownMatches(userHometown, dish.origin_cuisine)` → +0.30. 用户家乡从 `user_profiles.hometown_cuisine` 优先, 缺失退 `getUserPrefs().hometownCuisine`.
- **A4 prefScores**: 严格复刻 `useWeeklyMenu.ts scoreForWeek` 公式:
  - `usagePower(n) = sign(n) * |n|^1.5 * 0.05`
  - `sigmoidWeight = 0.35 + 1.15 * (1 - exp(-learnedSignals/15))` (cold-start 0.35, 30 信号 1.34, ∞ 1.50)
  - flavor / health tag ×0.6 × sigmoidWeight, cuisine ×1.0 × sigmoidWeight
  - DB load: `user_profiles.pref_scores` (jsonb 形态 `{score, n}`) 先 unwrap, 再退 `user_preference_scores`
- **A6 family per-member**: 每个 home member 独立算 goal hit (+0.30) + allergy ingredient hit (-0.20), 总分 = 加权平均 (除以家人数, 防止家人多了分爆). `GOAL_TO_DB_TAGS` inline 复制一份 (避免广播改 familyPrefs API).
- **A7 feature_vector 20-dim cosine**: 加 `dish.feature_vector` 字段到 SELECT, 用户 `preference_vector` 存在 → `cosineSimilarity(userVec, dishVec) * 0.25`. dish 缺 vector → 现场 `dishToVector(d)` 兜底 (跟 cascade 模式一致). 用户缺 vector → 直接 skip 这一轴, 不 break.

### B. "+加今日菜单" 落地 (`src/pages/Home.tsx`)

- dish card 主区 (点 → `/prep`) 行为不动. 卡 layout 从 outer `<button>` 改为 `<div>`, 主区改成 inner `<button>`, 右下角加 pill.
- pill: 橙色 `#FF5A1F`, 11pt, "+ 加今日{slotLabel}" (lunch / dinner 按 `dish.course_type` 自动判, 没 course_type 默认 dinner — CEO 拍板减少点击不弹 sheet).
- 点击 → `addScanDishToTodayMenu(dish)`:
  1. upsert `user_weekly_menus` 当前 weekStart + todayIdx + slotMeal 行, dish.id append 进 `dish_ids[]` (dinner 行同步维护 `swapped_dish_ids`).
  2. 必填 `algo_version + cache_key` (口径跟 `swapDish` 完全一致, 否则下次 `loadFromDB` 判 stale 抹掉)。`getCacheKey(weekStart)` 同源算法保证 key 跟 useWeeklyMenu 自身 100% 对齐.
  3. 去重: 已在 baseIds → toast "已在今日{slotLabel}" 不重复加.
  4. 成功 → 抹本 week localStorage cache + dispatch `nutri-weekly-menu-changed` 让其他实例失效.
- pill 状态: 加入中 (disabled, opacity 0.6) → "✓ 已加入今日{slotLabel}" (灰底, disabled).
- toast: modal 顶部 absolute 浮层, 黑底白字, 2.2-2.8s 自动消失.

### 实施约束

- 不 bump ALGO_VERSION (scanMatch 不进 weekly_menu cache, 只是 cache_key/algo_version 必填以兼容下游 loadFromDB stale check).
- import 全部走 static (避免 vite dynamic+static dual import warning).
- 不改 `familyPrefs.ts` 公共 API (只 inline 一份 GOAL_TO_DB_TAGS 镜像).
- 不动 `/prep` 跳转路径 (老板没说删).

## 3. 标准

今后任何新推荐入口必须满足:

1. **算法**: 跟主算法对齐. 任何"简化版"评分函数都是技术债 — 至少要接 hometown + prefScores + family per-member + feature_vector 这 4 轴. 简化版会导致用户感知"我的偏好在不同入口被遗忘".
2. **落地**: 推荐出来的菜必须有一键写回 `user_weekly_menus` 的路径. 用户做了"采纳"动作但下次打开 app 找不到 = 体验割裂. upsert 必带 `algo_version + cache_key` (跟 swapDish 同口径), 否则下次 loadFromDB 把这行判 stale.
3. **缓存失效**: 写入后必须 dispatch `nutri-weekly-menu-changed` event + 抹本周 localStorage cache, 让 useWeeklyMenu 重新读 DB. 否则 Home/WeeklyMenu 页菜单 stale.
4. **CEO 减少点击原则**: 能用 dish 元数据自动判的 (slot/数量) 就别弹 sheet 让用户选.
