# HK Stripe 个人 sole proprietor 注册 — 国家锁定坑 (2026-05-26)

## 1. 问题

老板想用美国 Stripe 账户切香港，进 Stripe Dashboard 找了一圈 "Country" 改不动。
背景：之前测试过个人 Stripe 美国账户但没激活，现在要做 HK 业务需要 HKD 收款，
US 账户不支持。老板假设"在 personal info 里改国家"——错。

真因：**Stripe 一旦账户创建好，Country 字段就锁死，永远不能改**。改 currency 也不行。
唯一办法是**用不同邮箱重新注册一个 HK 账户**。这一点 Stripe 没明确警告，新手很容易卡半天。

## 2. 方法

**新 HK 个人账户注册流程**：

1. 不要 logout 旧 US 账户，直接打开 stripe.com/register 用**新邮箱**注册（不能用原邮箱）。
2. Country 下拉**首屏就选 Hong Kong**——错过这步就要重来。
3. Business type → **Individual / Sole Proprietor**（个人独资），不要选 Company（公司需要 BR 证）。
4. 个人信息：HK 身份证号 / HK 地址 / HK 手机号都要真，audit 会查。
5. 银行账户：HKD 账户，最好 HSBC / Hang Seng / BOCHK 等 HK 本地银行（用 Wise 等虚拟银行 audit 可能慢）。
6. 提交后进**审核状态**（1-3 工作日），审核期间：
   - 可以在 Dashboard 看，可以拿 test key，但 **live key 拿不到**。
   - **不能发 real test webhook**——live mode 未激活 webhook test 按钮灰着。
   - 审核通过会发邮件，然后 live key 才能复制。

**审核通过后立刻做的 3 件**：
1. Activate live mode → 复制 `pk_live_*` + `sk_live_*`。
2. Webhooks → Add endpoint → 选 6 个事件 `checkout.session.completed` /
   `customer.subscription.{created,updated,deleted}` / `invoice.payment_{succeeded,failed}`,
   保存后立刻复制 `whsec_*`（只显示一次，关了再回去就要 reveal）。
3. Products → 建 HKD 三档 (Pro 月/年/终身)，拿到 `price_xxx`，**3 处同步更新**：
   - `src/pages/Pricing.tsx`
   - `supabase/functions/stripe-webhook/index.ts` ALLOWED_PRICE_IDS
   - `supabase/functions/create-checkout-session/index.ts` 同名白名单

**找事件的搜索坑**：Stripe Webhook 创建里搜事件名时，
API version 默认是 `2026-04-22.dahlia + preview`——这个版本下搜框要求**清空再输部分关键词**
（如 `checkout` 而不是 `checkout.session.completed` 整名），否则匹配为 0。

## 3. 标准

**今后涉及 Stripe 账户操作的不变量**：

1. **国家选择只有一次机会**：注册前确认目标市场货币和审核管辖区，不要用占位邮箱测试。
2. **审核期不要发真 webhook**：live mode 未激活时 webhook test 必然失败，等审核完再测。
3. **Webhook signing secret 只显示一次**：复制后立刻贴 Railway 和 Supabase 两处，
   关闭页面后 reveal 需要重新点 reveal，万一权限收回会丢。
4. **live price_id 必须在 live Stripe 创建**：test 模式的 price_id 在 live mode 触发
   silent 4xx，是隐蔽 bug——白名单更新前先在 Stripe Dashboard 切到 live mode 双确认。
5. **绝不在 git / Slack / 截图发任何 sk_live / whsec**：粘进 Railway 或 Supabase 的 secret 面板，
   不要 echo 到终端，不要写 markdown。CLAUDE.md 已要求"never commit env / credentials"。
