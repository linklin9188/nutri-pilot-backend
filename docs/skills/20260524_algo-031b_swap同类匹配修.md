# Swap 算法同类匹配修（TICKET-031b）

**任务**：换菜算法把"鱼换成鸡"，老板期望同类（鱼换鱼）。算法层修，优先 protein family 硬匹配。
**完工时间**：2026-05-24 HKT

## 1. 解决了什么问题

老板真测 `/home` 红烧鲫鱼点"换菜"，候选出大盘鸡 / 意式柠檬鸡 / 葱烧海参（截图都标 "MEAT"）。

**实查根因**（不是 CEO 诊断的"算法退回到 category fallback"，DB 里没 category 列。真因更直接）：

`src/hooks/useSupabaseMenu.ts:fetchSwapOptions` 把 `course_type='main_protein'` 当唯一硬过滤，
把 `main_ingredient` 退化成软排序。`main_protein` 同 course_type 的鸡 / 鸭 / 牛 / 猪 / 鱼 / 海参全部
共池——同 main_ingredient='fish' 候选数（38）远小于全 main_protein 池（>200），软排序前置 38 道鱼之后，
3 个候选很容易**全部超出 fish 切到其他主料**。

数据层不是 0 行 null（924/924 有 main_ingredient），但 **218 道是 'other'**（24%）+ 海鲜散在 12 个细 token
（fish/salmon/seabass/hairtail/shrimp/...）+ 鸡禽散 3 token (chicken/duck/poultry)——细粒度不一致让算法只看
main_ingredient 等值匹配不够。

## 2. 用了什么关键方法

### 算法层修（不依赖 DB backfill 就能 ship）

1. **新增 `proteinFamilyOf()`**（`useSupabaseMenu.ts`）—— 把零散 main_ingredient 聚合到 4 大 family：
   - `red`: beef / pork / lamb
   - `white`: chicken / duck / turkey / poultry
   - `seafood`: fish / shrimp / crab / squid / scallop / clam / oyster / salmon / tuna / cod / seabass / hairtail / shellfish / seafood
   - `veg`: tofu / egg / soy / mushroom / veggie / vegetable / bean
   - `''` (unknown): other / carb / dessert / fruit / grain / dairy / rice — 非主蛋白类目

   **注意**：这个函数与 `useWeeklyMenu._proteinClassOf` 同源（red/white/seafood/veg 4 类）但本地化在
   `useSupabaseMenu` 避免跨 hook 循环 import。改 family 映射必须同步两处。

2. **`fetchSwapOptions` 加 3 层 family 过滤**（在原 course_type 硬过滤之后）：
   - L1 **strictSameFamily**（最优）：候选 `proteinFamilyOf === currentFamily`
   - L2 **sameFamilyOrUnknown**（兼容 218 道 'other'）：family 同 OR family=''
   - L3 **cross-family 殿后兜底**：极端 0 候选场景才出现
   - 选择规则：L1 >= count 用 L1；否则 L2 >= count 用 L2；都不够才退 L3

3. **保留原"同 main_ingredient 软排序"**（在 family pool 之内做精细排序，鱼内 fish > salmon > seabass）

4. **被换菜 family='' 时跳过 family 过滤**（兼容 main_ingredient='other' / 'carb' 等场景，仍走 course_type only）
