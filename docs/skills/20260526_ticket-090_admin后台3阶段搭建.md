# TICKET-090 admin 后台从零搭建 — 3 阶段 + 双 build (2026-05-26)

## 1. 问题

老板要在上线前能"看订单 + 看 commission + 看用户增长"，但 Aieats 没有任何 admin
后台。Supabase Dashboard 太原始（直接看表，没业务聚合），第三方 BI 工具上手太重。
需要一个**独立部署 + 简单密码登录 + 3 个核心视图**的 admin 站。

约束：
- 不能动主站架构（CLAUDE.md 双 runtime, custom auth）
- 不能用 Supabase Auth（user_profiles 全 anon-first，admin 用户也不进 auth.users）
- 不能把 admin 数据请求走前端 anon key（绕不过 RLS）
- 必须能查跨表聚合（orders + commission + user_profiles），还要 export CSV

## 2. 方法

**架构**：在主 monorepo 加 `admin/` 子项目 + 在 `server.js` 加 `/api/admin/*` endpoint。

- `admin/` = 独立 Vite React 应用，build 输出 `admin/dist/`
- 主 `server.js` 加路由 `/admin/*` 静态 serve `admin/dist`，加 `/api/admin/*` 数据接口
- 部署：Railway 同一个 service，build 脚本加 `npm run build:admin` 一并构建

**3 phase 分割**（防一锅端）：

- **Phase 1**: Orders 页 + 3 个 backend endpoint（`/api/admin/orders` `/api/admin/stats` 等）
  + requireAdmin middleware（Basic Auth + SHA256 password hash 验证）
- **Phase 2**: Commission 页 + `/api/admin/commission` + migration 100 加
  `admin_monthly_commission` VIEW（按月+supplier 聚合）+ CSV 下载（带 BOM 防 Excel 乱码）
- **Phase 3**: Users 页 + Dashboard 总览 + 左侧 nav + 4 个 route

**关键技术决定**：

1. **password 用 SHA256 哈希**：`ADMIN_PASSWORD_HASH` 存 Railway env，不存明文。
   admin 登录时前端发明文，server 哈希后对比。生产用 bcrypt 更稳但 SHA256 够用（单用户）。
2. **service_role key 只在 server.js 用**：admin 数据请求都从 server.js 中转，
   service_role bypass RLS 直接查全表。绝不暴露给 admin/ 前端 bundle。
3. **CSV 加 UTF-8 BOM**：`﻿` 开头，否则 Excel 打开中文乱码。
4. **summary + recent 拆开返**：summary 是聚合数字（卡片），recent 是 list（表格），
   一个 endpoint 一次返两份，前端少跑一次请求。
5. **每个数据接口写 503 fallback**：env 缺 SUPABASE_URL / SERVICE_ROLE_KEY 时返
   `"supabase not configured"`，让 ops 一眼定位是部署配置漏。

**环境变量清单**（必填到 Railway）：
```
ADMIN_USERNAME=link
ADMIN_PASSWORD_HASH=<sha256(password)>
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...  # Legacy tab 取
```

**3 phase 顺序的好处**：每 phase 一个 commit + 部署 verify。
不会出现"5 个文件改一半推不上去"的死锁。Phase 1 ship 后老板能立刻看 Orders 验证，
Phase 2 + 3 follow up 是叠加，不破坏 Phase 1。

## 3. 标准

**今后所有"admin / 内部工具站点"搭建的不变量**：

1. **独立 sub-app + 同 monorepo**：admin 不要拆远程 repo，分支管理太重；用 `admin/` 子目录
   + 独立 `package.json` + `npm run build:admin` 输出 `admin/dist`。
2. **password 哈希存 env，不存明文**：SHA256 / bcrypt 任选，绝不裸字符串。
3. **数据请求必须经 server.js 中转**：service_role key 严禁前端，admin 前端只发请求不发查询。
4. **3 phase 分割**：先 ship 一个最简能用版本，老板真测确认方向对了再加。
   一次性做完 Dashboard + Users + Orders + Commission + Subscriptions 必出问题。
5. **CSV 导出加 BOM**：`Content-Type: text/csv; charset=utf-8` + `﻿` 开头。
6. **每个 endpoint 写 env-missing fallback**：返 503 + 明文原因，不要 500 露 stack。
7. **classifyUser 等业务逻辑集中在 server helper**：不在 SQL VIEW 和前端两处分叉。

**部署 verify checklist**：
- `curl /api/admin/orders -H 'authorization: Basic ...'` 返 200
- `curl /api/admin/stats` 返 JSON 含 real_users 字段
- admin/login 输入正确账号密码进 Dashboard
- 错误密码返 401
