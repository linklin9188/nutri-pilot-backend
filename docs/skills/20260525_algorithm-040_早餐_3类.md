# 20260525 Algorithm TICKET-040 — 早餐 spec 校准 (4 类 → 3 类)

## 一段话讲清楚改了啥

早餐之前要求 4 大营养类全覆盖 (碳水 / 蛋白 / 蔬菜 / 水果)，老板 2026-05-25
凌晨拍板把"蔬菜 + 水果"合并成"维生素"一类——也就是说蔬菜和水果**任意一个**
有就够了，不强制两者都要。`useWeeklyMenu.ts` 的 breakfast supplement 逻辑从
"缺哪个补哪个 (AND)" 改成"两者都缺才补一个 (OR)"，bump v65 → v66 让所有
旧缓存失效。

## 为什么这样改

老板原意：早餐 4 件主要是为了营养结构完整，但实际上"维生素来源"在中餐早餐
里蔬菜和水果是等价的（橘子 vs 凉拌青菜 都给 vitC + fiber）。强制两者各 1
道在工程上不难，但对用户来说菜量过多 + 早餐时间紧，反而不符合真实家庭场
景。3 类 spec 是产品上的简化，不是算法降级。`breakfastCombos.ts` 的 4 类
分类 (carb/protein/veg/fruit) 保留——数据结构仍有用 (slot candidates 同类
补菜、reader)，只是 supplement gate 改成 OR。补菜时优先尝试 fruit pool
(晨起易消化、不需要烹饪步骤)，fruit 空再退 veg。

## 怎么验证

1. 清浏览器 localStorage 或换新用户 → 刷 /weekly-menu → 看早餐 slot 数：
   - 正常 combo 自带 veg 或 fruit (e.g. 港式皮蛋瘦肉粥 + 油条 + 茶叶蛋
     可能不含 veg/fruit) → 算法补 1 道 fruit (e.g. 橘子)
   - combo 已自带 veg (e.g. 凉拌黄瓜) → 不再补 fruit，3 件即够
   - combo 已自带 fruit (e.g. 苹果) → 不再补 veg，3 件即够
2. `grep "v66"` 应在 `useWeeklyMenu.ts:124` 命中
3. `breakfastCombos.ts` 不动 (本 ticket 只改 supplement 逻辑)
