# TICKET-112 P0 — /chef "加入今晚" 真写当日菜单 (2026-05-30)

## 问题
agent-first MVP /chef (ChefAgent.tsx) 的"加入今晚"只写 toggleFavorite (占位),
没真写进菜单 → 采购清单和菲佣端都看不到雇主在 chef 点的菜。P0 要把这"最后一公里"接通。

## 方法
新建 src/lib/chefAddToToday.ts `addDishToTodayMenu(dishId)`:
- upsert user_weekly_menus, onConflict `user_id,week_start,day_index,meal_type` (同 ChatAgent handleAdopt / saveToDB)
- 今天: weekStart=`getWeekStartISO(0)`, dayIndex 周一=0 (`getDay()===0?6:getDay()-1`), mealType ≤14点=lunch 否则 dinner
- merge 保命: 先 select 现有生效菜 (swapped 非空→swapped 否则 dish_ids) → append 去重 → 写回, 不丢已有
- 复用 getUserId / ALGO_VERSION(v72未bump) / getCacheKey; {error}+try/catch 双兜底

ChefAgent.tsx 接线: addToToday 改 async, 仍 toggleFavorite + 调 addDishToTodayMenu, 加 toast + 防抖。

## 关键坑 (对抗验证 agent 抓出来的)
**下游读者午/晚餐口径不一致**:
- 晚餐: helper + 采购(loadFromDB dinner) 都 **swapped 优先** → 晚餐写 `swapped_dish_ids`
- 午餐: 采购/WeeklyMenu 午餐格**只读 `dish_ids`**(不读 swapped) → 午餐若写 swapped, 采购午餐看不到
- 修法: **按餐次分列写** —— 午餐写 dish_ids, 晚餐写 swapped_dish_ids。两段各命中自己读者完整路径。

## 标准
1. 写共享缓存表前, 必须先读清楚**所有下游读者各自读哪一列/哪个口径** (本案午晚餐读法不同, 不核对就漏)。
2. 多 agent workflow 的 **对抗验证 phase 真有用** —— 实现 agent 选了 swapped(晚餐对), 验证 agent 才发现午餐缺口。find→verify 双 agent 值回票价。
3. 时区: getWeekStartISO 用本地, helperEmployerMenu 用 toISOString(UTC) — HK(UTC+8)无害, 美洲负偏移有跨日风险 (遗留, 记录备查)。
4. swapped_dish_ids = 用户对自动菜单的覆盖; 一旦写入, 该餐次后续自动重算(写dish_ids)会被 swapped 屏蔽直到清空 (列固有设计)。
