# i18n-051 — OnboardingV2 上 t3 三语言

## 一、问题 / 起因

OnboardingV2 是新用户落地的第一屏 (代替旧 QuickSetup 11 题). qa-047
audit 发现整页 122 行 0 个 useLanguage 调用 — en / tl / id 用户全看
硬编码中文. 新用户第一印象国际化破，老板明早上线必修，P0.

## 二、做了什么 / 怎么修

走 LanguageContext 现成的 `t3(en, zh, tl)` 三语言 helper. 不动 onboarding
主流程（step 流转 / dish 选择算法 / Supabase upsert 全不动），surgical
edit 只把硬编码字符串包进 t3.

具体：
- import `useLanguage` 注入 `const { t3 } = useLanguage();`.
- `REP_DISHES` 12 道代表菜 + `AVOID_OPTIONS` 9 个 chip + `GOAL_OPTIONS`
  5 选 1 + `GROUP_TITLES` 3 组 — 全部数据结构加 `labelEn` / `labelTl`
  / `descEn` / `descTl` 字段，render 处 `{opt.label}` → `{t3(opt.labelEn,
  opt.label, opt.labelTl)}`.
- 所有 hero / 按钮 / 错误提示文案直接 inline t3.
- dish title 走静态数据 不读 DB.title_en — 后续要更精准翻译再 fetch DB
  `title_en / title_zh_hant` 覆盖，本轮先用 onboarding 内嵌静态对照表.

## 三、踩了什么坑 / 经验

1. **数据结构 vs 渲染分层** — 不要在 GROUP_TITLES 直接放 t3 调用结果
   （那是组件外 const, t3 是 hook 输出），改成 `{ zh, en, tl }` 子对象，
   render 时取字段调 t3，避开 hook 调用规则.
2. **descEn / descTl optional** — REP_DISHES 的 `desc` 是 optional，加
   `descEn` / `descTl` 时同样保 optional，t3 调用用 `?? d.desc` 兜底
   避免 undefined 进 t3.
3. **build 验真** — vite build 通过即可 ship，不必跑 tsc（项目 prod
   build 走 vite 不走 tsc，CLAUDE.md 明确说"don't fix pre-existing
   ts errors"）.
