## 一句话讲完这事干啥

用户在采购清单页面看到"由 XX 供货商直供"标签 → 点"一键下单"按钮 → 跳到供货商那边（WhatsApp 或网站）下单 → 我们后台偷偷记下"谁点了什么"，每周给供货商一份报表（"这周你的食材被推荐多少次 / 多少人点 / 热门菜是哪些"）。

## 第一版**做**这些

1. **供货商档案** — 名字 / Logo / WhatsApp 号 / 落地页链接 / 类别（意大利菜 / 日本菜 / 有机等）
2. **食材清单** — 每个供货商可以卖多个食材，每个食材记：食材名 / 图 / 价格 / 单位 / 一键下单链接 / "推给哪些菜"的关键词匹配规则
3. **用户点击记录** — 用户每次点"一键下单"，记一行：谁点的 / 点的是什么食材 / 从哪道菜来 / 从哪个页面来 / 时间
4. **采购清单页面改造** — 命中供货商覆盖的食材，行右边加"由 X 直供"小标签 + "一键下单"按钮
5. **你的管理后台加 3 个新页面**：
   - **供货商管理**：列表 + 新增 / 编辑 / 暂停 / 激活
   - **食材管理**：按供货商筛选，新增 / 编辑 / 删除 / 上架下架；重点是改"关键词匹配"规则
   - **导流报表**：按供货商 × 每周聚合：本周点击数 / 独立用户数 / 热门食材 Top 5 / 热门来源菜 Top 5

---

## 第一版**不做**这些

- ❌ 不在 Aieats 里收钱（用户直接在供货商那付）
- ❌ 不做实时库存 / 实时价格同步
- ❌ 不做配送追踪
- ❌ 不给供货商自己上架后台（你管理员手动维护）
- ❌ 不在菜单推荐算法里给"覆盖供货商的菜"加分（5 个食材影响太小，加分还会让算法被商业污染）

理由：先证明"导流模式能赚钱"再扩。连点击量都做不出，做支付 / 库存 / 配送都是浪费。

## 红线（这些我永远不做）

1. **不会**把你私人邮箱 / 微信 / 真名写进供货商或食材任何字段
2. **不会**做"独家排他"条款的功能（保留同时接多个供货商的空间）
3. **不会**让一键下单跳钓鱼 / 欺诈网站（后台审核必须校验是合法域名）
4. **不会**在点击记录里存用户的真实邮箱 / 手机 / 收货地址（只存内部 ID）

## 需要你拍板的 4 件事

### 1️⃣ 范围对吗？
上面"做"和"不做"清单有要改的吗？比如想加 / 想砍 / 想换。

### 2️⃣ 种子供货商名字
第一版我会先建一个**占位档案** `"Aieats Italian Partner (TBD)"`，等你跟真供货商谈完后改成真名字。

**两个选择**：
- **A** — 先建占位档案开干（推荐，不卡 4 棒进度），你谈完后管理后台改名即可
- **B** — 直接等你谈完再开干（4 棒接力延后到你确定供货商名字之后）
